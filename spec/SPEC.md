### 任务 1：算术逻辑单元（ALU）

你的第一个任务是创建一个 ALU，它支持我们 ISA（将在下一节详细介绍）中所有指令所需的操作。请注意，我们对待溢出的方式与 RISC-V 处理无符号指令时一样，也就是说，我们忽略溢出。

我们在 `alu.circ` 中为你提供了一个 ALU 的骨架。它有三个输入：

| 输入名称 | 位宽 | 描述 |
| --- | --- | --- |
| A | 32 | ALU 运算中输入 A 的数据 |
| B | 32 | ALU 运算中输入 B 的数据 |
| ALUSel | 4 | 选择 ALU 应执行的操作（见下方操作及其对应开关值列表） |

……以及一个输出：

| 输出名称 | 位宽 | 描述 |
| --- | --- | --- |
| Result | 32 | ALU 运算的结果 |

下面是需要你实现的 ALU 操作列表，以及它们对应的 ALUSel 值。所有操作都是必需的。允许并鼓励你使用 Logisim 内置模块来实现算术运算。**请注意，由于 Logisim 中新增了带符号乘法器，使得实现 mulh 变得和 mulhu 一样简单，因此 mulh 不再是额外加分的项目了。**

| 开关值 | 指令 |
| --- | --- |
| 0 | add：`Result = A + B` |
| 1 | and：`Result = A & B` |
| 2 | or：`Result = A | B` |
| 3 | xor：`Result = A ^ B` |
| 4 | srl：`Result = (unsigned) A >> B` |
| 5 | sra：`Result = (signed) A >> B` |
| 6 | sll：`Result = A << B` |
| 7 | slt：`Result = (A < B (signed)) ? 1 : 0` |
| 8 | 未使用 |
| 9 | 未使用 |
| 10 | mul：`Result = (signed) (A * B)[31:0]` |
| 11 | mulhu：`Result = (A * B)[63:32]` |
| 12 | sub：`Result = A - B` |
| 13 | bsel：`Result = B` |
| 14 | mulh：`Result = (signed) (A * B)[63:32]` |

在实现 `mul` 和 `mulh` 时，注意乘法模块有一个 "Carry Out" 输出（加法器模块也有这个，但你不需要用到它）。

你可以对 `alu.circ` 做任何修改，但输出**必须**遵循上述规定的行为。如果你创建了额外的子电路，它们也必须放在 `alu.circ` 中（你不能新建 `.circ` 文件）。此外，你的 ALU **必须**能够放入提供的测试装置 `alu_harness.circ` 中。这意味着你应该注意不要移动输入或输出。要验证你的改动没有破坏任何东西，可以打开 `alu_harness.circ`，确保没有错误且电路运行正常。

**提示：**

- `add` 已经为你做好了；在实现其他模块时，可以放心地使用类似的结构。
- 你可以将光标悬停在模块的输入/输出上，获取关于该输入/输出的更详细信息。
- 如果你想了解每个模块的更多细节，请前往 Help->Library Reference 获取关于该模块及其输入输出的更多信息。
- 在实现 `sra` 和 `srl` 时，你可能会发现位拆分器（bit splitters）或扩展器（extenders）很有用。
- 使用隧道（tunnels）！它们能让你的布线更整洁、更易读，并减少遇到交叉线或意外错误的机会。
- 在决定要输出哪个模块的输出时，多路选择器（MUX）可能会很有用。换句话说，可以考虑简单地在所有模块中处理输入，然后输出你选择的那一个。

### 任务 2：寄存器文件（RegFile）

正如你在课上学到的，RISC-V 架构有 32 个寄存器。对于本项目，**我们将实现全部 32 个寄存器**。为了便于调试，**我们编写了 regfile 使其暴露下面指定的 9 个端口**。请确保这些寄存器的值连接到正确的输出上。

你的 RegFile 应该能够在不影响任何其他寄存器的情况下，对给定 RISC-V 指令中指定的寄存器进行写入或读取。有一个值得注意的例外：即使某条指令试图写入 x0，你的 RegFile 也**不应**写入 x0。请记住，零寄存器（zero register）的值应**始终**为 0x0。你不应在 RegFile 中的任何位置对时钟进行门控（gate）：时钟信号应**始终**直接连接到寄存器的时钟输入端，而不经过**任何**组合逻辑。

暴露的寄存器及其对应编号如下表所示。

| 寄存器编号 | 寄存器名称 |
| --- | --- |
| x0 | x0 |
| x1 | ra |
| x2 | sp |
| x5 | t0 |
| x6 | t1 |
| x7 | t2 |
| x8 | s0 |
| x9 | s1 |
| x10 | a0 |

我们在 `regfile.circ` 中为你提供了寄存器文件的骨架。寄存器文件电路有六个输入：

| 输入名称 | 位宽 | 描述 |
| --- | --- | --- |
| Clock | 1 | 提供时钟的输入。该信号可以传入子电路，或直接连接到 Logisim 中存储单元的时钟输入端，但除此之外不应被门控（即不要对其取反，不要将其与任何东西做 "与" 运算等）。 |
| RegWEn | 1 | 决定在下一个时钟上升沿是否将数据写入寄存器文件。 |
| Read Register 1 (rs1) | 5 | 决定哪个寄存器的值被送到 Read Data 1 输出，见下文。 |
| Read Register 2 (rs2) | 5 | 决定哪个寄存器的值被送到 Read Data 2 输出，见下文。 |
| Write Register (rd) | 5 | 决定在下一个时钟上升沿将哪个寄存器设置为 Write Data 的值（假设 RegWEn 为 1）。 |
| Write Data (wb) | 32 | 决定在下一个时钟上升沿（假设 RegWEn 为 1）将什么数据写入由 Write Register 输入所标识的寄存器。 |

寄存器文件还有以下输出：

| 输出名称 | 位宽 | 描述 |
| --- | --- | --- |
| rs1 | 32 | 由 Read Register 1 输入所标识的寄存器的值驱动。 |
| rs2 | 32 | 由 Read Register 2 输入所标识的寄存器的值驱动。 |
| `ra` Value | 32 | 始终由 `ra` 的值驱动（这是一个调试/测试输出）。 |
| `sp` Value | 32 | 始终由 `sp` 的值驱动（这是一个调试/测试输出）。 |
| `t0` Value | 32 | 始终由 `t0` 的值驱动（这是一个调试/测试输出）。 |
| `t1` Value | 32 | 始终由 `t1` 的值驱动（这是一个调试/测试输出）。 |
| `t2` Value | 32 | 始终由 `t2` 的值驱动（这是一个调试/测试输出）。 |
| `s0` Value | 32 | 始终由 `s0` 的值驱动（这是一个调试/测试输出）。 |
| `s1` Value | 32 | 始终由 `s1` 的值驱动（这是一个调试/测试输出）。 |
| `a0` Value | 32 | 始终由 `a0` 的值驱动（这是一个调试/测试输出）。 |

你 `regfile.circ` 文件顶部的测试输出是为了测试和调试而设置的。如果你是在实现一个真正的寄存器文件，你会省略那些输出。但在我们的情况下，请确保它们被正确包含——如果没有，你将无法通过。

你可以对 `regfile.circ` 做任何修改，但输出必须遵循上述规定的行为。如果你创建了额外的子电路，它们也必须放在 `regfile.circ` 中（你不能新建 `.circ` 文件）。此外，你提交的 `regfile.circ` **必须**能够放入我们提供的 `regfile_harness.circ` 文件中。这意味着你应该注意不要移动输入或输出。要验证你的改动没有破坏任何东西，可以打开 `regfile_harness.circ`，确保没有错误且电路运行正常。

**提示：**

- 充分利用复制粘贴！最好先完整地做好一个寄存器，然后把它作为模板来复制其他寄存器，以避免重复劳动。
- 我建议你不要使用 MUX 上的 enable 输入。实际上，你可以关闭这个功能。我还建议你把 "three-state?" 也关闭。看看 Logisim 寄存器的所有输入，了解它们各自的作用。
- 再次强调，MUX 是你的朋友，但 DeMUX 也是。
- 想想一条指令执行完毕后寄存器文件中发生了什么。哪些值改变了？哪些值保持不变？寄存器是时钟触发的——这意味着什么？
- 请记住，寄存器除了时钟输入外，还有一个可用的 "enable" 输入。
- `x0` 的值是什么？

### 任务 3：`addi` 指令

作为 Part A 的最后一项任务，你将实现一个能够执行一条指令——`addi`——的 CPU！你也可以在此时实现其他指令，但在 Part A 中，我们只会检查 `addi` 是否能够正确执行。在 Part B 中，我们会提供有关实现其他指令的更详细说明。

#### 说明：内存

内存单元（位于 `mem.circ`）已经为你完整实现，并在 `test_harness.circ` 中连接到了 CPU 的输出端。`addi` 指令不会使用内存单元，因此在 Part A 中，可以不驱动这些输出。

请注意，所提供的内存按字寻址，但支持按字节写入使能。这意味着 `Write_En` 信号的位宽为 4，并且会作为输入数据的写掩码。例如，如果 `Write_En` 为 `4'b1000`，那么只有内存中目标字的最高有效字节会被覆盖。无论 `Write_En` 为何值，`ReadData` 端口始终返回内存中指定地址处的值。

其输入和输出概述如下：

| 信号名称 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `WriteAddr` | 输入 | 32 | 内存中需要读取或写入的地址 |
| `WriteData` | 输入 | 32 | 要写入内存的值 |
| `Write_En` | 输入 | 4 | 执行内存写入指令时使用的写掩码；其他情况下为 0 |
| `CLK` | 输入 | 1 | 由 CPU 的时钟输入驱动 |
| `ReadData` | 输出 | 32 | 指定地址中存储的数据 |

#### 说明：分支比较器

框架中提供的分支比较器单元（位于 `branch_comp.circ`）尚未实现。不过，`addi` 指令不会使用分支比较器，因此在 Part A 中不需要考虑它。

如果你感兴趣，下面是其输入和输出的简要说明：

| 信号名称 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `rs1` | 输入 | 32 | 要比较的第一个寄存器中的值 |
| `rs2` | 输入 | 32 | 要比较的第二个寄存器中的值 |
| `BrUn` | 输入 | 1 | 进行无符号比较时为 1，进行有符号比较时为 0 |
| `BrEq` | 输出 | 1 | 两个值相等时为 1 |
| `BrLt` | 输出 | 1 | `rs1` 的值小于 `rs2` 的值时为 1 |

#### 说明：立即数生成器

框架中提供的立即数生成器（Immediate Generator，简称 “Imm Gen”，位于 `imm_gen.circ`）尚未实现。`addi` 指令需要立即数生成器，但目前可以将其硬连线为只构造 `addi` 指令的立即数，而无须考虑其他类型的立即数。

要编辑这个子电路，请编辑 `imm_gen.circ` 文件，而不是编辑 `cpu.circ` 中的 `imm_gen`。请注意，如果修改了这个电路，需要关闭并重新打开 `cpu.circ`，CPU 才能加载这些更改。

其输入和输出概述如下：

| 信号名称 | 方向 | 位宽 | 说明 |
|---|---|---:|---|
| `inst` | 输入 | 32 | 当前执行的指令 |
| `ImmSel` | 输入 | 3 | 决定如何重新构造立即数的值 |
| `imm` | 输出 | 32 | 指令中的立即数值 |

#### 说明：处理器

我们在 `cpu.circ` 中提供了处理器框架。在构建数据通路时，你需要使用自己实现的 ALU 和寄存器堆（RegFile）。整个数据通路需要由你从头构建。

对于 Part A，完成后的处理器应当使用两级流水线支持 `addi` 指令：

- 第一级为 IF。
- 第二级包含 ID、EX、MEM 和 WB。

不过，我们建议你首先创建一个不使用流水线的单周期处理器。确认它能够正常工作后，再将其修改为两级流水线处理器。

你的处理器会被放置在处理器测试框架 `test_harness.circ` 中，该框架包含内存单元。这个处理器测试框架又会被放置在测试框架 `run.circ` 中，由后者向处理器提供指令。

你的处理器需要输出一条指令的地址，并接收该地址处的指令作为输入。它还需要输出数据内存地址和数据内存写使能信号，并接收该地址处的数据作为输入。从本质上讲，这两个测试框架分别充当数据内存和指令内存。

建议你花些时间检查 `test_harness.circ` 和 `run.circ`，以准确了解它们的工作方式。我们提供的基本检查测试会使用 `test_harness.circ`，因此在测试和提交之前，请确保你的 CPU 能正确嵌入该测试框架。

处理器必须向第一级测试框架提供以下输出：

|---|---:|---|

| `s1` | 32 | 输出 `s1` 中的内容，用于测试 |

与 ALU 和寄存器堆一样，请注意不要移动任何输入或输出引脚！有关测试框架和测试的更多信息，请参阅“测试”一节。

#### 说明：控制逻辑

框架中提供的控制逻辑单元（`control_logic.circ`）尚未实现。设计控制逻辑单元很可能是 Part B 中最大的挑战。

对于 Part A，可以为每个控制信号设置一个常量，因为你只需要实现 `addi` 指令。在实现 `addi` 时，也请思考：为了支持其他指令，之后需要在哪些位置添加逻辑。

要编辑这个子电路，请编辑 `control_logic.circ` 文件，而不是编辑 `cpu.circ` 中的 `control_logic`。请注意，如果修改了这个电路，需要关闭并重新打开 `cpu.circ`，CPU 才能加载这些更改。

你可以根据控制逻辑的需要，为现有的初始电路添加更多输入或输出。你也可以根据需要使用任意数量的已有端口。不过，在此过程中请不要修改或删除任何已有端口。

#### 单周期 CPU：指导

我们知道，从一张白纸开始构建 CPU 可能令人望而生畏，因此编写了以下指南来帮助你。

回顾 CPU 流水线的五个阶段：

1. 取指（Instruction Fetch，IF）
2. 指令译码（Instruction Decode，ID）
3. 执行（Execute，EX）
4. 访存（Memory，MEM）
5. 写回（Write Back，WB）

本指南将帮助你逐步完成 `addi` 指令的各个阶段。每一节都会提供一些需要思考的问题，并指出重要细节，但不会直接告诉你应该如何实现这条指令。

在进入下一个问题之前，你可能需要阅读并理解当前问题。单击问题即可查看答案。在实现过程中，你可以根据需要将不同部分放入子电路。

#### 阶段 1：取指

这一阶段主要关注的问题是：如何取得当前指令？

根据课堂内容，我们知道指令存储在指令内存中，并且可以通过地址访问其中的每条指令。

1. 项目中的哪个文件包含指令内存？它如何连接到 `cpu.circ`？

   指令内存是 `run.circ` 中的 ROM 模块。它向 CPU 提供一个名为 `INSTRUCTION` 的输入，并从 CPU 接收一个输出。在 `cpu.circ` 中，这个输出称为 `PROGRAM_COUNTER`；在 `run.circ` 中，它称为 `fetch_addr`。

2. 在 CPU 中，更改作为 `PROGRAM_COUNTER` 输出的地址会如何影响指令输入？

   `run.circ` 向 CPU 输出的指令，应当是指令内存中地址为 `PROGRAM_COUNTER`（或 `fetch_addr`）处的指令。

3. 如何知道 `PROGRAM_COUNTER` 应该是什么值？

   `PROGRAM_COUNTER` 是当前正在执行的指令的地址，因此它保存在 PC 寄存器中。在本项目中，PC 从 0 开始，因为寄存器的默认值为 0。

4. 对于不包含跳转或分支的基本程序，PC 在相邻指令之间应当如何变化？

   为了前往下一条指令，PC 必须递增一条指令的长度，因为 PC 寄存器中的地址表示需要执行哪条指令。这意味着在没有分支或跳转的情况下，PC 通常每次增加 4。

在 `cpu.circ` 中，我们提供了一个简单的 PC 寄存器实现，它暂时忽略跳转和分支。你将在项目的 Part B 中实现分支和跳转，但现在只需要关注如何运行 `addi` 指令。

请记住，我们最终需要实现一个两级流水线处理器，因此 IF 阶段与其余阶段相互分离。什么电路可以分隔流水线的不同阶段？具体来说，什么电路将 IF 与下一个阶段分隔开？你是否需要添加任何东西？

#### 阶段 2：指令译码

现在，指令已经从指令输入端进入 CPU。接下来需要按照你所学习的 RISC-V 指令格式，在指令译码阶段将它拆分为不同字段。

1. `addi` 属于哪种类型的指令？它包含哪些位字段？每个字段使用哪些位？

   `addi` 是 I 型指令。各字段如下：

   - `imm[31:20]`
   - `rs1[19:15]`
   - `funct3[14:12]`
   - `rd[11:7]`
   - `opcode[6:0]`

2. 在 Logisim 中，应该使用什么工具拆分不同的位组？

   使用分线器（Splitter）！

3. 使用指令输入实现指令字段译码阶段。你应使用隧道（Tunnel）标记并组织这些位。

4. 现在需要通过寄存器堆取得相应寄存器中的数据。哪些指令字段应该连接到寄存器堆？应该连接到寄存器堆的哪些输入？

   指令字段 `rs1` 需要连接到“读取寄存器 1”（Read Register 1）。

5. 实现从寄存器堆读取数据。你需要导入自己在 Part A 中实现的 RegFile。请记得连接时钟！

6. 立即数生成器需要完成什么工作？

   对于 `addi`，立即数生成器从指令中取得 12 位立即数，并生成一个经过符号扩展的 32 位立即数。你需要在立即数生成器子电路中实现此逻辑。

#### 阶段 3：执行

大多数指令的计算都在执行阶段完成。我们还会在这里引入控制模块的概念。

1. 对于加法指令，ALU 的输入应该是什么？

   读取数据 1（`rs1`）以及立即数生成器产生的立即数。

2. 在 ALU 中，`ALU_Sel` 有什么作用？

   它决定 ALU 执行哪种运算。

3. 目前可以直接将一个常量作为 `ALUSel`，但为什么在实现更多指令后，这种做法不可行？

   对于不同的指令，ALU 可能需要执行不同的运算，因此你需要某种电路，根据当前执行的指令改变 `ALUSel`。

4. 导入你的 ALU，并正确连接 ALU 的输入。是否需要连接时钟？为什么？

#### 阶段 4：访存

在访存阶段，可以使用存储指令向内存写入数据，也可以使用加载指令从内存读取数据。由于 `addi` 指令不使用内存，因此这里不会花费太多时间。

目前，我们还不能连接其中的大多数输入，因为尚不知道这些输入应当来自哪里。

#### 阶段 5：写回

写回阶段会将运算结果保存回寄存器。

1. `addi` 指令是否需要将结果写回寄存器？

   是。`addi` 会取得 ALU 加法运算的结果，并将其写回寄存器堆。

2. 创建写回阶段，使其能够把 ALU 或 MEM 的输出写入寄存器堆。

   稍后实现分支和跳转时，可能需要向这个多路选择器添加更多输入。不过目前只需要在 ALU 输出与 MEM 输出之间进行选择，因为寄存器堆的一个输入端最终只能连接一条线路。分别从 ALU 和 `READ_DATA` 引出一条线，并将它们连接到一个多路选择器（MUX）。

3. MUX 的选择输入应当使用什么？该输入取决于什么？

   该输入应当能够在以下三个 MUX 输入之间进行选择：

   1. ALU
   2. MEM（`READ_DATA`）
   3. PC + 4（思考一下什么时候会使用它）

   决定将其中哪个输入写回的控制信号称为 `WBSel`。目前，`WBSel` 应该只会取一个值，也就是 `addi` 所需要的值。

4. 现在已经整理好了 MUX 的输入，接下来需要连接其输出。输出应连接到哪里？

   因为该输出就是要写入寄存器堆的数据，所以应将它连接到寄存器堆的 Write Data 输入端。

5. 寄存器堆还有两个对写入数据非常重要的输入：`RegWEn` 和 `rd`。其中一个来自指令译码阶段，另一个则是你需要在 Part B 中设计的新控制信号。请正确连接 RegFile 的这些输入，从而完成写回阶段。

如果正确完成了以上所有步骤，你现在应该已经拥有一个能够执行 `addi` 指令的单周期处理器。

运行以下命令，检查它是否能够正常工作：

```bash
python3 test_runner.py part_a addi_single
```

#### 将 CPU 流水线化

现在是时候在 CPU 中实现流水线了！

本项目要求实现一个两级流水线。它在概念上仍然与课堂和讨论课中介绍的五级流水线相似。如果你还没有复习相关内容，请先进行复习。

需要实现的两个阶段是：

1. **取指（Instruction Fetch）**：从指令内存中取得一条指令。

2. **执行（Execute）**：对指令进行译码、执行和提交（写回）。这一阶段结合了普通五级 RISC-V 流水线中剩余的四个阶段：ID、EX、MEM 和 WB。

由于所有控制和执行工作都在执行阶段中处理，除启动时多出一个周期的延迟以外，你的处理器在外部表现上应该与单周期实现大致相同。不过，我们会强制要求采用两级流水线设计。

需要考虑以下问题：

- IF 阶段和 EX 阶段中的 PC 值相同还是不同？
- 是否需要在流水线的两个阶段之间保存 PC？

你可能还会注意到一个启动问题：在第一个周期中，位于两个流水线阶段之间的指令寄存器还没有保存从内存中加载的指令。应当如何解决？

Logisim 在复位时会自动将寄存器设为 0，因此指令寄存器此时会包含一条 `nop` 指令。我们允许你依赖 Logisim 的这一行为。请记得通过菜单 **Simulate → Reset Simulation** 重置处理器；快捷键为 macOS 上的 `Cmd + R` 或 Windows 上的 `Ctrl + R`。

完成处理器的流水线化后，你应该能够通过以下测试：

```bash
python3 test_runner.py part_a addi_pipelined
```

请注意，此时单周期测试会失败，这是预期行为。为什么？请重新查看每个测试的参考输出，并思考流水线会对不同阶段产生什么影响。

#### 测试

##### 理解测试

每个测试都是初始代码所包含的 `run.circ` 文件的一个副本，其中的指令已经加载到 IMEM 中。

从命令行运行 Logisim Evolution 时，时钟会不断跳变，程序计数器会递增，并且各输出端的值会被打印到标准输出 `stdout`。

以单周期 `addi` 测试为例，其中包含 3 条 `addi` 指令：

```text
addi t0, x0, 5
addi t1, t0, 7
addi s0, t0, 9
```

在 Logisim Evolution 中打开：

```text
tests/part_a/addi_pipelined/cpu-addi-pipelined.circ
```

仔细查看测试文件中的各个部分。在文件顶部，你会看到 CPU 与测试输出相连接的位置。使用初始代码时，所有值都会显示为 `xxxx`；当 CPU 正常工作时，则不应该出现这种情况。

CPU 接收一个输入，即指令。除了输出各寄存器中的值之外，它还有一个额外输出：`fetch_addr`，也就是需要从 IMEM 取出的指令地址，该指令将在下一个时钟周期执行。

请勿移动 CPU 的任何输入或输出，也不要添加额外的输入或输出。这样做会改变 CPU 子电路的形状，导致测试文件中的连接无法正常工作。

在 CPU 下方可以看到指令内存。3 条 `addi` 指令对应的十六进制机器码已经加载到指令内存中：

```text
0x00500293
0x00728313
0x00928413
```

指令内存接收一个名为 `fetch_addr` 的输入，并输出该地址处的指令。

`fetch_addr` 是一个 32 位值，但由于 Logisim Evolution 将 ROM 单元的最大容量限制为 \(2^{16}\) B，因此必须使用分线器，只从 `fetch_addr` 中取得 14 位，并忽略最低的两位。

请注意，`fetch_addr` 是字节地址，而不是字地址。

那么，当时钟跳变时会发生什么？

每次时钟跳变，测试文件中名为 `Time_Step` 的输入都会递增。时钟会持续运行，直到 `Time_Step` 等于该测试文件的停止常量。对于这个特定的测试文件，停止常量是 5。

届时，Logisim Evolution 命令行会将各输出端的值打印到标准输出。测试程序会将你的输出与预期输出进行比较；如果二者不同，测试就会失败。
